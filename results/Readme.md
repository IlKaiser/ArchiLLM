# Evaluation Metrics for Microservice Architecture Generation

This document outlines the metrics used to evaluate the **completeness**, **granularity**, and **cohesion** of microservice architectures (MSA) generated by the system.

## 1. User Stories Metrics
These metrics assess how effectively the input requirements (User Stories) are translated into the architectural design.

### User Stories Satisfaction Coverage (USSC)
* **Definition**: Measures the extent to which the input user stories are addressed in the generated output. It represents the percentage of unique user stories covered across all generated microservices.
* **Formula**: 
    $$USSC = \frac{\sum_{i=0}^{n} US_i}{\text{Total Input US}}$$
  
  
    Where $US_i$ is the number of user stories implemented by the $i^{th}$ microservice (excluding duplicates).

### Average User Stories per Microservice (AUSM)
* **Definition**: Measures the average number of user stories assigned to each microservice. This provides insight into the functional density and granularity of the application.
* **Formula**: 
    $$AUSM = \frac{\sum_{i=0}^{n} US_i}{N_{\text{microservices}}}$$

  
    Where $US_i$ is the number of user stories in a single microservice $i$, and the denominator is the total number of generated microservices.

---

## 2. Endpoint & Granularity Metrics
These metrics evaluate the quality of the service boundaries and the complexity of the internal operations.

### Average Lack of Cohesion Metric (ALCOM)
* **Definition**: Quantifies the average similarity and relatedness of operations within the services by calculating the Lack of Cohesion (LCOM) for each microservice. 
* **Scale**: 0 to 1.
    * **Values closer to 1**: Indicate lower cohesion (higher system complexity and potential for errors).
    * **Values closer to 0**: Indicate high cohesion.

### Average Service Granularity Metric (ASGM)
* **Definition**: Measures the balance of the system's granularity by considering the number of inputs and outputs of its endpoints. It is the product of two sub-measures:
    1.  **Data Granularity of a Service (DGS)**: Assesses whether operations use excessive data.
    2.  **Functional Granularity of a Service (FGS)**: Measures how evenly operations are distributed across services.
* **Formula**: 
    $$SGM = DGS \times FGS$$
* **Scale**: 0 to 1.
    * **0**: System is too fine-grained.
    * **1**: System is too coarse-grained.
    * **~0.5**: Optimal balanced granularity.

---

## 3. Supplementary Data Indicators
In addition to the calculated metrics, the following raw data points are tracked:

* **RUS**: Total number of Raw User Stories defined in the input.
* **GUS**: Total number of Generated User Stories included in the MSA.
* **TS**: Total number of Services generated (Total Services).

---

## 4. Qualitative Patterns Evaluated
The evaluation also considers the presence of specific **Data Patterns** in the generated stubs:
* **API Composition**: Aggregating data from multiple services.
* **Saga**: Coordinating distributed transactions.
* **Event Sourcing**: Recording state changes as immutable events.
* **CQRS**: Separating command and query responsibilities.
